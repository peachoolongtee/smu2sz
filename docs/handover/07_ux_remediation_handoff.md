## 4. What a build session should know

- **ADR-0011 is the contract for every decision surface.** The record is a read model over the canonical stores, plus one small append-only table, `decision_facts` (migration 0006), for the three facts that cannot be re-derived: EVALUATED (the verdict's day), SENT (the counter shown, the books version, the economics, the gap plan) and QUOTED (the legs, costs, landing, after-state and if-declined the owner was shown when a cure was queued). Pages derive agreement, authorization, execution and settlement from the record, never from a clicked button or a verdict outcome.
- **The write points are exactly three**, all in the API layer, inside the route's `rt.lock`, after the canonical event: `POST /offers/{id}/evaluate` writes EVALUATED, `POST /negotiate/{id}` writes SENT, `POST /alerts/{id}/act` writes QUOTED (also when every leg was refused). `POST /approvals/{id}`, `POST /clock/advance`, `POST /operations` and `/nl` write nothing; their effects already sit in the approvals, the log, the commitments and the lots. Writes go through the one helper `record_fact()` in `app/api/decisions.py`, which never fails a route (it logs, and the response says `decision_recorded: false`). Do not write a fact inside the executor's unit of work.
- **Never recompute history.** A missing fact is shown as "not recorded" ("quoted cost was not recorded"). Do not fill it from today's alert, today's plan or today's books; that is the fault (F13, F03) the record exists to end. A decision written before the record has state but no quote.
- **Chat and direct operations have no quote.** `nl:` decisions and `approval:` records get identity and state only (debt item). Recording the plan shown in an earlier turn is a follow-up.
- **Known executor behaviour, recorded not changed.** `/negotiate` funds the gap in the same call as a queued accept, which moves the books, so approving that accept later is refused ("The books changed since verdict ...") and the record reads FAILED. Also `fen_of` in `app/api/quotes.py` reads money back from the alert's display strings.
- **The stability gate.** No module under `app/financial`, `app/verifier`, `app/funding`, `app/alerts`, `app/operations`, `app/clock`, `app/books` or `app/mandate` changed in the remediation. Check it again after any change: `git diff --stat 742847f HEAD -- services/api/app/financial services/api/app/verifier services/api/app/funding services/api/app/alerts services/api/app/operations services/api/app/clock services/api/app/books services/api/app/mandate` must print nothing, and `tests/decisions/test_isolation.py` must pass (no engine module names the record; loading the engine does not load it; the record imports only `app.domain` and `app.persistence.records`). The golden digests must not move. Engine sentences are hash-chained and stay English; Business wording and Chinese are said on top by `app/api/engine_zh.py` and `app/api/presentation.py`.
- **The mock recorder.** Mock files under `apps/web/mocks` are recordings; never edit one by hand. Start an API with `DEMO_MODE=1` on a free port (not 8000; the default is 8011), then `node apps/web/scripts/record-mocks.mjs --api http://localhost:<port>` (or `pnpm mocks:record`). It resets the books and walks the demo stepper, the pages and the chat through the same client code the browser uses, and writes the decision record as snapshots in `decisions.json` that `lib/mock/decisions.ts` chooses among by the mock's story state. Run twice it must leave `git status --short apps/web/mocks` empty. Any change to a response the web reads means a re-record; `scripts/check-mocks.test.mjs` checks the files. `--strategy` records only `mocks/strategy/` and needs the three strategy flags on the API.
- **The e2e switches.** Defined in `apps/web/playwright.config.ts`. `E2E_TARGET=mock|live|all` chooses the servers (`pnpm test:e2e:mock`, `pnpm test:e2e:live`). `E2E_REUSE_API=1` starts no API: the live project runs against one already listening on `E2E_API_PORT` (start it yourself with `CORS_ORIGINS` set to the live web origin). `E2E_DATABASE_URL` is the `DATABASE_URL` of the API Playwright starts (default `memory`; for example `sqlite:////absolute/path/e2e.db`) and has no effect with `E2E_REUSE_API=1`. `E2E_STRATEGY=1` builds the web app with `NEXT_PUBLIC_STRATEGY_MVP=1` in its own dist directory and starts the API with the three strategy flags; the counts then differ (mock 135 default and 144 with it, live 69 and 77, per report section 12). `E2E_PORT` (mock, 3100), `E2E_LIVE_PORT` (3000) and `E2E_API_PORT` (8000) move the ports; use one set per worktree. Retries are zero. The live web build runs with a 6 s request timeout so `slow.spec.ts` can show the slow notice (production uses 20 s, and 60 s for the long reads).
- **The phone order mechanism.** `apps/web/lib/use-narrow.ts` is a `useSyncExternalStore` over `matchMedia("(max-width: 63.999rem)")`: true below 1024 px, false on the server. Home (`app/page.tsx`), Deals (`app/deals/page.tsx`) and Cash (`app/cash/page.tsx`) use it to change the DOM order, so focus and reading order follow what is on screen; every part keeps its key so its state survives a resize. It never decides what is shown, only the order, and the desktop order is unchanged. The gate is `e2e/responsive.spec.ts` ("phone priority", 412 x 915): each page's primary action must end inside 915 px (Home 785, Deals 823, Cash 799 in the report). The `touch:` variant in `app/globals.css` is a block form, because the documented `pnpm dev` returned 500 on the old invalid custom variant; `e2e/touch.spec.ts` fails on the old CSS.
- **The Demo story's convergent steps.** `apps/web/lib/demo.ts` holds the six scenes and eleven steps. Every step brings the books to at least its own state and, when they are already there, only reads them again; that is what makes Replay and a second Run safe on a story that moves time. Show only opens a finished step's screen and never resets the clock; a step runs only after the one before it; the stepper is locked (a module-level `inFlight` guard beside the store's `busy`) while a step runs; the approve step is the owner's own click and the stepper never presses it; the clock never records a receipt, so the one receipt in the story is the Demo-only `POST /demo/bank-receipt` (owner token, `DEMO_MODE`, reference `DEMO-RCPT-1`). Narration is built from the server's responses; a unit test (`scripts/w6-demo.test.mjs`) forbids figures in the dictionary's step text. The walk is `docs/DEMO_FLOW.md`; its test is `e2e/demo.spec.ts`, mock and live, including the rapid-click test that fails on the old code.
- **Rules that held through the remediation**, from the earlier handoffs: INVARIANT 13 (the browser computes no money; the server writes every sentence, now in both languages); all API changes additive with defaults unchanged; one branch per task merged with `--no-ff`; plain one-line commit messages with no co-author trailers; `git checkout -- services/api/evals` after scenario, attack or evaluation runs.
