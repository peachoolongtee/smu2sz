## 2. Architecture and trust boundaries

Paths are under `services/api/` unless stated. Arrows are data flow; **bold** components may change financial state.

```
UNTRUSTED                     TYPED / DETERMINISTIC                                 STATE
buyer message, email,  ──►  compiler (app/compiler/service.py, boundary.py,  ──►  CompiledOffer (typed obligations,
attachment, term sheet        rules grammar; LLM only in LLM_MODE=live, behind        each with an exact source span)
(POST /offers, POST /nl       a JSON schema with no operation/approval fields)            │
 as COUNTERPARTY)                                                                         ▼
uploaded contract      ──►  contract reader (app/compiler/contract.py) ──► ContractRecord PROPOSED ──► owner confirms
(POST /documents)             never books anything (ADR-0012)                             (CONFIRM_DOCUMENT, logged)
                                                                                          ▼
                            verifier (app/verifier) + funding router (app/funding) ◄── books, signed mandate, menu
                            sees typed rows only; produces a Verdict and a plan
                                                                                          ▼
owner (X-Owner-Token) ──►   operations built by code from the Verdict  ──►  **executor (app/operations/executor.py)**
agent (X-Agent-Key)         tier computed by app/mandate/tiers.py              gates, Tier 2 queue, admission
bank feed (X-Bank-Feed-Key)                                                    ──► **store (app/persistence)**:
                                                                                   books, commitments, approvals,
                                                                                   hash-chained operation log
                            outbound text: templates + egress guard (app/egress/guard.py) ──► buyer
monitoring: clock posts scheduled flows (app/clock), alerts + reconciliation (app/alerts), Activity/Home/Deals reads
```

- **Untrusted input enters** at `POST /offers` and `POST /nl` (buyer text), `POST /documents` (uploaded files, owner-only
  route but adversarial content), the `context` and query parameters of owner reads (`app/api/selection.py` validates ids
  against the stores), and, in live mode, model output.
- **Sensitive data** (cash, reserve, floor, mandate caps, facility terms, other buyers' terms, contract clauses) is
  readable only through owner-token routes, with the documented exception R-11 (agent key through chat). Outbound text to
  a buyer passes the egress guard (`app/egress/guard.py`, `protected.py`, `contracts.py`).
- **Only the executor changes the books**, inside a store unit of work, writing a log entry for every outcome
  (`app/operations/executor.py` `execute`, `decide`, `revoke_commitment`, `decide_document`). Exceptions to check, not
  assume: `POST /demo/reset` and `POST /demo/restore` reload fixtures and **erase the log** (owner-only;
  `app/api/read.py`, `app/api/demo_story.py`); the clock posts scheduled flows (`app/clock`, `POST /clock/advance`, owner
  or bank feed); customer inputs append context rows, not books (`app/api/customer_inputs.py`).
- **Simulations:** the buyer, lenders and the bank are simulated. `POST /demo/bank-receipt` (owner + `DEMO_MODE`) books a
  synthetic receipt; the bank-feed key records receipts as SYSTEM.
- **Business and Demo modes** are web presentation (`apps/web/lib/mode.ts`); they do not change server authority. The web
  keeps the owner token in `sessionStorage` and sends it as `X-Owner-Token` (`apps/web/lib/auth.ts`). Mock mode
  (`NEXT_PUBLIC_*` mock build) accepts any non-empty token in the browser and never calls the API.
