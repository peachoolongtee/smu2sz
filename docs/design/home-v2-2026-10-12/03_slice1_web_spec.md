## What wave 2 builds (desktop and phone), rendered only when `/health` features.home_v2 is true AND the Home read carries `home_v2`; otherwise the existing Home, untouched
1. **The header**: "Home", the status dot + word, "Read today" (the existing `home-read-when`).
2. **The company strip** (a `Card` with three cells, hairline dividers): CASH AVAILABLE (value, note, the `CashBufferIndicator`: a thin scale with the minimum mark and the cash dot, from `kpis.cash_available.buffer`; not a progress bar); LOWEST CASH AHEAD (value with tone, note, `with_plan_hint` as a hint line); PLANNED FUNDING / FUNDING ARRANGED (eyebrow from the read, value, note, hint). No sparklines.
3. **The action bar** (`DecisionCard`, one line): `home_v2.action` with its eyebrow, title, text; when `control` is RUN_PLAN or APPROVE_PLAN the existing confirm-and-run control (`usePlanRun`, the same `fix-open-*` / `fix-*` / `fix-cancel-*` ids and the waiting state) is the one filled primary, "Compare" the secondary; when `control` is null the quiet variant with no filled button.
4. **The company cash chart** (a `Card`): the timeline component in its compact variant (reuse components/home/event-picture.tsx's SVG and series handling; no new chart): the current-books line, the minimum, the plan line as the grey dashed comparator when the plan is planned (legend from `chart.legend` with kinds current | planned | hypothetical rendered as solid / grey dashed / brand dashed), the lowest point marked with the cause text from the read, the lowest-point click opening the inspector (`chart.lowest_inspector` rows) under the chart (`--dur` reveal, Esc closes), the window word (36 · 60 · 120 as SegmentedTabs without icons), `chart.note` and "Full timeline in Cash & Funding ›". No event rail. Hover tooltip from the series' effect rows when present.
5. **The link row** from `home_v2.links` (a quiet `Card`, thin dividers).
6. **The worklist panel** (right column, 360 px; a `Card`): the alert pinned above the tabs when present (red tone, "Run or compare ›" scrolling to the action bar); SegmentedTabs "Needs you N | Waiting N | Customers N" with the counts from the read, a badge only on Needs you when N > 0; the search box filtering the fetched rows by `search_terms` (client-side filtering of already-fetched strings is allowed; no computation); three row shapes (`ActionRow` for needs_you and waiting, `CustomerRow` for customers), each row: dot (owner tone), subject, status, consequence, a severity word at the right (`StateWord`-styled, CRITICAL / CAUTION / NORMAL); the first needs-you row shows `why_first_text` under it; the hint line per tab; "All deals ›" / "All customers ›". Row click in wave 2: a needs-you or waiting row navigates to its `href` (the full workspace) and a customer row to /customers/{id}; wave 3 replaces that with the in-place focus. `is_new` renders a quiet "new" word; the list never reorders while a row is focused (re-sort only on a fresh load or when focus leaves the panel).
7. **Phone (390)**: the strip as three rows, the action, the chart, then a "Worklist (N)" button opening a bottom sheet with the tabs and rows (the existing sheet component if one exists, else a simple `role="dialog"` with focus trapped, Esc closes, `--dur-expanded`); the primary in the first viewport.
8. **Mocks**: record `/worklist` and `/customers` and the Home read with FEATURE_HOME_V2=1 for the day-0 and after-plan states (new files; the existing Home recordings stay for the flag-off page); the mock serves the V2 read when a session key `tl-mock-home-v2` is set (the pattern the Home hybrid used), so both pages are testable.
