# UX remediation ledger, 9 October 2026 (map #65, Wave 0, ticket #67)

Version 1. Written by the Wave 0 verifier. It changes no product code.

## What this ledger is

The independent flow audit ([independent-flow-ux-audit-2026-10-09.md](independent-flow-ux-audit-2026-10-09.md)) found 28
issues, F01 to F28. This ledger is the single list that tracks each one from "reported" to "fixed and checked". One row per
finding. A row says whether the finding was reproduced on current `origin/dev`, what the real technical cause is, what fix is
proposed, which files it touches, what the response looked like before and what it should look like after, and the status.

- Baseline: `origin/dev` at `024ae1ec` (detached worktree `.claude/worktrees/w0-api`). The audit's baseline was `e15e3ee`.
- Runtime: fresh API on port 8031, `TERMSLEDGER_NO_DOTENV=1 DATABASE_URL=memory LLM_MODE=cache DEMO_MODE=1`, demo credentials.
- Evidence: every transcript is a JSON file under [ux-remediation-2026-10-09/api/](ux-remediation-2026-10-09/api/). Each file holds
  `request` (method, path, body, credential header names), `clock_day_before_request`, `status` and `response`. Multi-step
  setups (reset, offer, evaluate, negotiate, clock moves, bank receipt) are logged in one `<probe>-setup.json` per walk. The
  scripts that made them are in `ux-remediation-2026-10-09/api/probe-scripts/`.
- Replay of the audit's own probes: `api/replay-of-audit-probes/` against the audit's saved JSON, field by field, in
  `api/replay-diff-vs-audit.txt`. Result: every response matches the audit except fields that are hashes or ids
  derived from hashes (for example commitment `CMT-a811295f3a59b55f` now, `CMT-09c5b5e58e424153` then) and the
  `/ledger` snapshot, which the audit took after a completed fifteen-step demo while the replay ran on a fresh server.
- Not a fix list in itself. Nothing here is implemented. STATUS describes the finding, not code.

## Shared root-cause groups

Fixing a group once closes several rows. Group names are used in the ROOT CAUSE column.

| Group | What is wrong | Rows |
| --- | --- | --- |
| Time semantics | A day number is turned into words relative to "today" with no difference between a past, immutable event and a current eligibility. Pre-today days of the projection are filled with today's cash. | F01, F03, F25 |
| Decision identity | A decision (quote, terms, authority, result) is rebuilt from current alerts and plans every time it is read, so it changes or vanishes once the world moves. There is no durable decision record. | F02, F12, F13, F14 |
| Lifecycle state | "Acceptable", "agreed", "executed", "refused", "expired" are derived in the browser from partial local facts instead of from the stored lifecycle. | F04, F06, F14 |
| Historical vs current projection | Sentences or figures read from the current books are shown as if they described the moment of the event (and the reverse). | F01, F03, F13, F17 |
| Context propagation | The language, the selected deal or the page context is not carried to every read that writes words. | F08, F20, F28 |
| Frontend-local status | The browser keeps its own copy of progress and results (demo store, local result text) and does not re-read the server after a terminal answer. | F06, F09, F10, F14 |
| Demo orchestration | The guided story omits the late-payment loop and can restart itself. | F09, F10, F11 |
| Presentation duplication | The same fact is built in two places with different rules, so they disagree. | F12, F17, F18, F25 |
