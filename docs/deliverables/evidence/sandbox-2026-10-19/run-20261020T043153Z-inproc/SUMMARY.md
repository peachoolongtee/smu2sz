## Failures and differences from the documents

- No step failed.
- Case 3b: after "1" has shown the item (its reply says: To approve it, say "approve APR-…"), "approve 1" is not understood and decides nothing; the approval stays PENDING (fail-safe), and "approve APR-…" then decides it. "approve 1" directly after the numbered list decides it (case 3c), as Table 8 of docs/SECURITY_SELF_ASSESSMENT.md states: a bare pick after "yes" only shows the item (CON-1).
- Case 2d: with the bank-feed key and the agent key together, an unpaused DRAW_FACILITY sent as SYSTEM is not refused: it is rewritten to the agent's own request and runs at the agent's Tier 1 within the mandate, as docs/SECURITY_SELF_ASSESSMENT.md 1.2 and services/api/app/api/operations.py describe. The bank-feed key confers no SYSTEM authority beyond a receipt: alone it gets 401; while paused the same draw is refused (PAUSE-1).
- Case 4c: the compensating repayment of docs/SECURITY_SELF_ASSESSMENT.md Table 11 is itself judged by admission (Table 5): with the gap still open, repaying the ¥150,000.00 draw on day 0 would leave ¥60,000.00 on day 12, so it is REFUSED. The first version of this script expected it to execute; the expectation was corrected to the documented rule.
- Case 5 (5.06): while paused, the buyer's offer still leaves a PROPOSED commitment record (no money moves; not agreed), as docs/SECURITY_SELF_ASSESSMENT.md 1.11 states; the acceptance itself is refused.
- Case 2b: the buyer's claim is answered with a Tier-1 COUNTER_OFFER (EXECUTED on the chain: a reply, not an agreement); no acceptance, commitment or money movement follows.
